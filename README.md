# 环绕影院 · Vision Pro 220° 沉浸播放器 v1.1

自己用的本地视频环绕播放器。先说清楚：**普通视频没拍到的画面是不存在的，变不出真 360 素材**。这个应用做的是环绕播放器——视频贴在你前方的沉浸大屏上，在 Vision Pro 里就是沉浸式看片。

度数按 Apple TV 沉浸视频的标准定：Apple 的沉浸片是 180° 起、能延到 230°，我们取 **220°**——画面在正前方展开、余光里还有，不用转身。360° 留给真 360 素材。

## 文件

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面结构：选片、模式切换、播放控制 |
| `app.js` | 全部逻辑：three.js 场景、拖动视角、播放控制、WebXR 检测 |
| `style.css` | 深色样式，手机端自适应 |
| `README.md` | 本文件 |

three.js 已打包在本地（three.min.js，r128），不依赖 CDN，离线也能加载 3D 模式。万一 three.js 没加载出来，页面不会白屏：顶部会出现一句明确提示，自动退回普通 2D 播放（选片和播放控制照常用，球幕和影院模式不可用）。

## 在 Vision Pro 的 Safari 里怎么用

1. 在 Vision Pro 上打开 Safari，进入这个页面（可以先在 Mac 上起个静态服务器，或部署到你自己的 Workers/VM 上再打开链接）。
2. 点「📂 选择本地视频」，选一个视频文件。视频只在浏览器里播，**不上传**。
3. 选模式：
   - **🎬 220° 沉浸**（默认）：视频铺在正前方 220° 的半球内侧，和 Apple TV 沉浸视频一个路子。**普通视频用这个模式**，转头能看到边缘，不用转身。
   - **🎬 180° 沉浸**：Apple 沉浸视频的标准角度，画面铺满正前方 180°，普通视频也可以用它；转头能看到边缘，不用转身。
   - **🎬 70° 沉浸**：手机镜头拍到的范围大概 65°，加 5° 就是 70°。普通视频铺在正前方 70° 的曲面屏上（按 16:9 比例做，水平 70°、垂直约 39°），比平时看电视大一点，四周是黑的，像关了灯的影院。
   - **🎬 90° 沉浸**：照 70° 的做法，屏按 16:9 比例做，水平 90°、垂直约 51°，整个画面一眼能看全。
   - **🎬 110° 沉浸**：照 70° 的做法，屏按 16:9 比例做，水平 110°、垂直约 62°，整个画面一眼能看全。
   - **🎬 130° 沉浸**：照 70° 的做法，屏按 16:9 比例做，水平 130°、垂直约 73°；屏比视野宽，左右两边要转头才看得到，跟 220° 一个道理。
   - **🎬 150° 沉浸**：照 70° 的做法，屏按 16:9 比例做，水平 150°、垂直约 84°；屏比视野宽，左右两边要转头才看得到，跟 220° 一个道理。
   - **🎥 影院模式**：视频放在前方一块大曲面屏上，背景是暗色星空和渐变。
   - **🌐 360° 球幕**：视频贴在整球内侧。真 360 视频（等距长方形 equirectangular）用这个模式效果才是对的；普通视频不要用这个，会被拉得太开。
   - **🥽 3D 立体**：给立体片源用（左右并排 SBS / 上下并排 OU）。画面铺在正前方 180° 沉浸屏上（照 Apple TV 沉浸视频的路子）；普通屏幕上只预览左眼那一半（右上角有角标说明），点「🥽 进入沉浸模式」后左右眼各看各的半幅，才是真立体。源格式在模式按钮下方选：自动（按文件名猜，含 sbs/3d 猜 SBS、含 ou/上下猜 OU，再不行看宽高比）/ 手动 SBS / 手动 OU。普通 2D 视频别用这个模式，会把画面劈成两半。
   - **🤖 AI 2D转3D**：给普通 2D 视频用——浏览器里实时跑 AI 深度模型估每帧远近、合成右眼画面，凭空造出立体感（参照 Owl3D 的路线，它家网页版工具用的就是同一个小模型）。第一次点这个模式才下载推理库和约 27MB 模型（之后走浏览器缓存），全程本地、不上传。普通屏幕上是左右并排（SBS）预览，点「🥽 进入沉浸模式」后左右眼各看一块屏才是真立体。模式下方有视差强度滑杆（0–5%，默认 2.5%）和实时状态行（下载进度 / 推理 fps / 用的 WebGPU 还是 WASM）。
   - **📺 2D 原格式**：不拉伸、不包围，普通视频按原格式平铺播放，跟普通播放器一样。
4. 下面是播放控制：播放/暂停、进度条（点一下就跳）、音量、全屏。想让画面更大：点「▣ 铺满窗口」，页面只剩播放器，再把 Safari 窗口拉大，画面就跟着变大，相当于把浏览器窗口本身当环绕屏；右上角「✕ 退出铺满」点一下恢复。
5. 如果浏览器支持 WebXR，会出现「🥽 进入沉浸模式」按钮，点一下就进沉浸式播放；不支持的浏览器上这个按钮直接隐藏，不会报错。

手机上也能打开看：拖动画面转动视角，控制条一样用。

## v1.1.1 修了什么（2026-11-17：AI 模式 Failed to fetch，改自托管）

- **毛病**：AI 模式在 VP、Mac、云端三处都报 `Failed to fetch`，约 30 秒后退回普通模式。根因是库和模型走海外 CDN 直连——transformers.js 库走 jsdelivr、模型走 HuggingFace，下载那一步拉不下来（模型文件 27MB 也超过了 Workers 静态资源 25MB 的单文件上限，没法直接放进站里）。
- **修法**：全部自托管。① 库 + WASM 运行时文件（transformers.js 3.8.1，与原来 jsdelivr 上拉到的版本逐字节一致，含 ort-wasm-simd-threaded.jsep.mjs/.wasm）放在本站 `/ai-lib/`；② 模型文件住在 GCP VM 的网站目录 `/var/www/html/models/onnx-community/depth-anything-v2-small/resolve/main/`（config.json、preprocessor_config.json、onnx/model_quantized.onnx，sha256 已核对与本地离线工具用的文件一致）；③ 本站 Worker 加了 `/models-proxy/` 路由，把模型请求转发到 VM 并走边缘缓存。页面从此只跟自己域名打交道，不再碰 jsdelivr / HuggingFace。
- **代码改动**：app.js 里 AI_CDN_URL 改成本站 `/ai-lib/transformers.min.js`；加载时把 `env.remoteHost` 指到本站 `/models-proxy/`、把 `env.backends.onnx.wasm.wasmPaths` 指到 `/ai-lib/`；wrangler.toml 加了 `main = "src/index.js"`（Worker 脚本 + 静态资源同站部署）。其余逻辑、数学、UI 一字未动。

## v1.1 改了什么（新增「🤖 AI 2D转3D」模式，网页里实时 AI 转立体）

- **新增第 12 个模式「🤖 AI 2D转3D」**：工具栏在 3D 立体和 2D 之间多了个按钮。给普通 2D 本地视频用：网页里实时用 AI 估深度、合成右眼，左眼原帧 + 右眼合成帧 = 立体。这是参照 Owl3D 的路线——它家网页版照片工具用的就是 Depth Anything V2 Small 在浏览器内推理；差别是它家桌面付费版用更大的模型在本地显卡上跑，画质和帧率都更高（见下面诚实说明）。
- **推理栈（懒加载）**：transformers.js v3（jsdelivr CDN 动态 import）+ `onnx-community/depth-anything-v2-small` 量化版（`dtype: 'q8'`，模型文件约 27MB），device 先试 WebGPU、起不来自动回退 WASM。只有第一次点这个模式才加载库和模型，页面正常打开不受影响；模型进浏览器缓存，之后再用秒开。WASM 线程数设为 min(4, 逻辑核数)。three.js 仍是本地打包、离线可用——只有 AI 模式需要联网下模型，下完之后断网也能转（缓存）。
- **流水线（和离线工具 convert.py 同一套做法）**：隐藏画布以 ≤448px 宽抓帧 → 深度推理（transformers.js 的 depth-estimation 管线，返回的 predicted_depth 已对齐回抓帧尺寸）→ 归一化（采样取 2%/98% 分位去极值，范围跨帧 EMA 平滑防深度"呼吸"；值越大越近，与离线版同口径）→ 最近 3 帧 0.25/0.5/0.25 时序平滑（离线版用前后帧，实时没法预知下一帧，改用最近三帧同样权重）→ 前向 warp 合成右眼（位移 = 深度 × 最大视差，单遍 z-buffer 取最近像素，空洞逐行取最近已写像素、优先背景一侧拉伸填充；离线版用 OpenCV inpaint，网页版用拉伸填充，边缘观感略糙但快得多）。
- **自适应节流**：推理忙时不排队，下一次推理间隔 = 上次耗时 ×1.05（下限 66ms、上限 600ms）——WebGPU 上能跑多快跑多快，WASM 慢就自动降频，不拖死页面。状态行每秒刷新真实推理 fps，不写死数字。
- **渲染**：复用 3D 立体模式的双屏 WebXR 结构——两块一模一样的 180° 屏贴 CanvasTexture（左 = 原帧画布、右 = 合成画布），沉浸时 layer 1/2 分眼（机制与 v1.0 在 three.min.js 源码里核实过的约定相同）。非沉浸的平面预览是第三块屏贴左右并排（SBS）拼接图，右上角常驻角标「🤖 AI 转 3D · 现在是左右并排预览 · 进 Vision Pro 沉浸模式看真立体」。视角 FOV 90°、左右转动限制同 180°/3D（±90°）。
- **UI**：模式下方设置行（只在 AI 模式显示）：视差强度滑杆 0–5%（默认 2.5%，和离线工具默认一致）+ 状态行（下载进度 % / 就绪后显示后端与推理 fps / 失败时显示真实原因）+ 一行说明（首次下载约 27MB、之后走缓存、视频不出本机）。铺满窗口时设置行跟其他设置行一起藏起来。
- **失败兜底**：模型加载失败、或热身帧推理失败 → 状态行如实写原因、自动切回 220° 沉浸普通播放，视频照常看；运行中连续 3 次推理出错同样停下并切回。绝不卡死、绝不假装在转。three.js 加载失败的 2D 降级里 AI 按钮一并禁用。
- **没动的**：原 11 个模式的几何、逻辑、文案、演示画面、选文件/拖放、全屏、铺满窗口、播放控制——全部原样。核心数学（归一化/平滑/warp）已用从 app.js 抽出的原函数在 Node 里跑过 10 项自测：近物在右眼精确左移最大视差量、空洞全填充、零视差时右眼与原帧逐像素一致，全过。
- **诚实说明（已知限制）**：① 网页版是 27MB 的小模型 + ≤448px 宽的深度图再拉伸上屏，深度精度、边缘质量、帧率都不及 Owl3D 桌面付费版的大模型 + 本地显卡——这是拿"免费、打开网页就能用"换的，状态行显示的 fps 是多少就是多少；② Vision Pro 真机的立体效果和帧率**未验**：visionOS Safari 的 WebGPU 可用性、WASM 速度、CanvasTexture 在沉浸下的刷新表现都要真机实测，若帧率太低，先把视差拉小没用（视差不影响推理耗时），只能等后续优化（比如降抓帧宽度或上 Worker 推理）；③ 推理跑在主线程，WASM 回退时推理的那几百毫秒页面会有可感知的卡顿，视频本身（解码在独立线程）一般不受影响；④ 深度是 AI 估的，不是测出来的：细发丝、透明/反光物体、快速运动的边缘会穿帮，和所有 2D 转 3D 工具一个毛病；⑤ 左右眼对应按标准约定（左眼 = 原帧、右眼 = 按"近物左移"合成）实现，若真机上发现立体感是反的（凹凸颠倒），反馈后把 warp 方向翻过来即可。

## v1.0 改了什么（新增「🥽 3D 立体」模式，真 per-eye 立体）

- **新增第 11 个模式「🥽 3D 立体」**：工具栏在 360° 球幕和 2D 之间多了个按钮。给立体片源用：SBS（左右并排，左眼=左半幅）和 OU（上下并排，左眼=上半幅）两种排布。
- **真立体的实现（不是把同一幅画给两只眼）**：同一个 video 建两份纹理——左眼纹理靠 repeat/offset 只采样源帧的左/上半幅，右眼纹理只采样右/下半幅——分别贴在两块一模一样的 180° 沉浸屏上（几何与 180° 沉浸模式相同，照 Apple TV 沉浸视频的路子）。进 WebXR 沉浸后靠 three.js WebXRManager 的约定分工分眼：已在本项目打包的 three.min.js 源码里核实过，左眼相机 `layers.enable(1)`、右眼相机 `layers.enable(2)`，且会话开始/结束会派发 sessionstart/sessionend 事件。所以沉浸时把左眼屏设到 layer 1（只有左眼看得见）、右眼屏设到 layer 2（只有右眼看得见），两只眼看到的是源帧的不同半幅，是真立体采样。
- **普通屏幕预览**：只显示左眼屏（左眼半幅画面，整幅铺在 180° 屏上），播放器右上角常驻角标「🥽 3D 源 · 现在显示左眼画面 · 进 Vision Pro 沉浸模式看真立体」；退出沉浸自动恢复成左眼预览。
- **源格式选择**：切到 3D 模式时，工具栏下方出现一行设置：自动 / SBS / OU。自动先看文件名（`上下`/`ou`/`tb` → OU；`左右`/`sbs`/`3d` → SBS），没线索再看宽高比（全幅 SBS 约 32:9、全幅 OU 约 16:18），都分不出来默认 SBS；设置行右侧实时写明当前按哪种采样，猜错了手动选即可。选文件时按文件名先猜一次，元数据加载后再按宽高比校正一次。
- **视角**：3D 模式 FOV 90°，左右转动限制同 180° 沉浸（±90°）；切换模式视角归零（老逻辑）。
- **没动的**：原 10 种模式的几何与逻辑、演示画面、选文件/拖放、全屏、铺满窗口、播放控制、three 加载失败的 2D 降级（3D 按钮一并禁用）——全部原样。
- **诚实说明**：① 立体效果只能在 Vision Pro 真机上验（本地没法渲染验证），左右眼对应关系按标准约定（SBS 左=左、OU 左=上，纹理 flipY 后 v∈[0.5,1] 为上半幅）实现，若真机上发现左右反了或上下反了，那是源片排布与约定不一致，手动换 SBS/OU 或反馈后再调；② VR180 那种每眼 180° 的 SBS 片源这样映射是对路的，普通 SBS 3D 电影铺在 180° 球面上会像 180° 沉浸模式一样拉伸填充，看的是沉浸感；③ WebXR 按钮出不出现仍取决于浏览器支持（Vision Pro 的 Safari 若不出按钮，3D 模式只能看左眼预览，这点和 v0.9 的诚实说明一致）。

## v0.9 改了什么（首屏重做：打开就有画面，不再是空播放器）

v0.8 的毛病：页面一打开是个空播放器——不选本地文件，video 就没有画面，3D 纹理全是黑的，只剩一句"先选一个本地视频文件"，看着像半成品。v0.9 治这个：

- **内置演示，打开就在播**：用一张画布实时画一段海面日出动画（星空渐隐、太阳贴着海面浮动、水里有反光、云慢慢飘；零文件体积、零版权），通过 `canvas.captureStream()` 把它喂给播放器本来就在用的那个 video 元素。10 种模式共用的都是这个 video 的纹理，所以演示在每种模式下打开就能看，还能拖动转视角试手感。画布隔帧绘制（约 30fps）省电。
- **演示有明确标识**：播放器左上角常驻一个角标「🎞 这是演示画面 · 点「选择本地视频」换成你的视频」；文件名位置显示"演示画面播放中"；时长位置显示"演示"（直播流没有总时长，进度条在演示期间不乱动）。选了自己的文件，演示立刻停掉、音量恢复成滑杆设置，一切照旧。
- **退路**：万一浏览器不支持 `captureStream`，演示画布直接铺在播放器里当 2D 演示播；点任意模式按钮或点播放器就撤下它，露出原来的选文件提示。three.js 加载失败退回 2D 播放时，演示流照样能在 2D 里播。
- **正式首屏**：副标题换成一句话价值"把普通视频，变成 Vision Pro 里的大银幕 · 本地播放，不上传"；播放器上方加了大号金色「📂 选择本地视频（只在本地播，不上传）」按钮和一行 10 种模式的名字预览；播放器下方新增「在 Vision Pro 上怎么用」四步说明（Safari 打开 → 选视频 → 选模式 → 铺满/全屏或添加到主屏幕）。原来那段很长的说明文字精简成一段，诚实口径不变（没拍到的画面变不出来、220° 是拉伸填充看环绕感）。
- **没动的**：10 种模式的几何、视角限制、FOV、拖动、铺满窗口、全屏、WebXR 按钮、选文件/拖放加载、本地不上传——全部原样。

其他功能都没动：three.js 本地打包、降级提示、PWA manifest。

## v0.8 改了什么（新增 90°/110°/130°/150° 沉浸模式）

- **新增 4 个沉浸模式**：工具栏模式切换里多了「🎬 90° 沉浸」「🎬 110° 沉浸」「🎬 130° 沉浸」「🎬 150° 沉浸」4 个按钮。沉浸类按钮按度数从小到大排：70°、90°、110°、130°、150°、180°、220°，然后是影院、360°、2D。来历：70° 试下来还是没调到满意的度数，就再加一排，让他一个一个试。
- **全部照 70° 的做法，屏按 16:9 比例做，不用上下通顶的球面**：画面高度 = 宽度 × 9/16，居中在正前方，半径同样 50，内侧贴视频纹理、不翻转，默认隐藏。几何参数（水平以 -Z 为中心，垂直以水平视线为中心）：
  - 90°：`SphereGeometry(50, 64, 40, 225°, 90°, 64.7°, 50.6°)`——水平 90°、垂直约 51°
  - 110°：`SphereGeometry(50, 64, 40, 215°, 110°, 59.1°, 61.9°)`——水平 110°、垂直约 62°
  - 130°：`SphereGeometry(50, 64, 40, 205°, 130°, 53.4°, 73.1°)`——水平 130°、垂直约 73°
  - 150°：`SphereGeometry(50, 64, 40, 195°, 150°, 47.8°, 84.4°)`——水平 150°、垂直约 84°
- **视角和转动**：FOV 保持 90°；左右转动限制在 ±宽度/2、上下限制在 ±高度/2 内，别转出屏幕外面去——90° ±45°/±25°（±0.79/±0.44）、110° ±55°/±31°（±0.96/±0.54）、130° ±65°/±37°（±1.13/±0.64）、150° ±75°/±42°（±1.31/±0.73）。切换模式时视角归零（老逻辑不变）。three.js 加载失败时 4 个新按钮也一起禁用。
- **诚实说明**：90°/110° 的屏能一眼看全；130°/150° 的屏比视野宽，左右两边要转头才看得到，跟 220° 一个道理，这是宽屏本身的道理，不是 bug。

其他功能都没动：铺满窗口、全屏修复、1600px 上限、FOV 逻辑、六个旧模式（包括 220°/180° 的球面做法，一个字没改）、WebXR 按钮、PWA manifest、拖动视角。

## v0.7 改了什么（新增 70° 沉浸模式）

- **新增「🎬 70° 沉浸」模式**：工具栏模式切换里多了第 6 个按钮，就在 180° 沉浸旁边。来历：2D 视频本身没有角度，手机镜头拍到的范围大概 65°（因手机而异），加 5° 就是 70°；普通视频铺在正前方 70° 的曲面屏上，比平时看电视大一点。
- **屏按 16:9 比例做，不用上下通顶的球面**：220°/180° 那种球面上下是通顶的（phi 全 180°），70° 要是照搬，画面会被上下裁掉一半。所以 70° 的屏水平 70°、垂直约 39°（70×9/16），居中在正前方：`SphereGeometry(50, 64, 40, 235°, 70°, 70.5°, 39°)`——水平以 -Z 为中心，垂直用 thetaStart/thetaLength 限制在 70.5°–109.5°。半径同样 50，内侧贴视频纹理、不翻转，默认隐藏。
- **视角和转动**：FOV 保持 90°（屏完整显示在视野中央，四周是黑的，像关了灯的影院）；左右转动限制在 ±35°（±0.61）、上下 ±20°（±0.35），别转出屏幕外面去。切换模式时视角归零（老逻辑不变）。

其他功能都没动：铺满窗口、全屏修复、1600px 上限、FOV 逻辑、五个旧模式（包括 220°/180° 的球面做法，一个字没改）、WebXR 按钮、PWA manifest、拖动视角。

## v0.6 改了什么（新增 2D 原格式模式）

- **新增「📺 2D 原格式」模式**：工具栏模式切换里多了第 5 个按钮，就在 360° 球幕后面。点它就藏起 3D 画布，直接显示 video 元素平铺在播放器里——复用已有的 `#video2d.show-2d` 样式（原比例、黑边留白），三个 3D 网格全部隐藏。播放、暂停、进度、音量控制条本来就控同一个 video 元素，不用改；2D 模式下拖动看视角自然失效（画布藏起来了），不用另外处理。
- **切换逻辑**：`setMode` 里切到 2D 时藏画布、显示 video；切回其他模式时恢复画布、藏起 video。FOV 在 2D 模式下不起作用，保持原值不动。three.js 加载失败时的降级逻辑保持原样（所有模式按钮禁用、video 直接显示）。

其他功能都没动：铺满窗口、全屏修复、1600px 上限、FOV 逻辑、四个旧模式、WebXR 按钮、PWA manifest、拖动视角。

## v0.5 改了什么（新增 180° 沉浸模式）

- **新增「🎬 180° 沉浸」模式**：工具栏模式切换里多了个按钮，就在 220° 沉浸旁边。实现和 220° 沉浸一个路子——球面一段、内侧贴视频纹理、不翻转，半径同样 50；半球从 180° 起、盖 180°，正好以正前方为中心。180° 是 Apple 沉浸视频的标准角度，普通视频用它正好。
- **视角**：180° 模式 FOV 90°，跟 220°/360° 一样；影院模式保持 75° 不动。
- **转动限制**：180° 模式下左右转动限制在 ±90° 内，别转到屏幕边缘外面去；220° 保持 ±115°；360° 和影院不限制。切换模式时视角归零（老逻辑不变）。

其他功能都没动：铺满窗口、全屏修复、1600px 上限、三种旧模式、WebXR 按钮、PWA manifest、拖动视角。

## v0.4 改了什么（播放器大小和视角）

v0.3 的问题：播放器平时卡在 960px 宽的框里，全屏还受 16:9 比例限制可能留黑边；Vision Pro 上把 Safari 窗口拉得再大，画面也不跟着变大，所以 220°/360° 看着都小。

- **新增「铺满窗口」模式**：播放控制条多了个「▣ 铺满窗口」按钮，点一下页面只剩播放器，播放器占满整个浏览器窗口（100vw × 100vh）。Vision Pro 上把 Safari 窗口拉多大，画面就多大。切 class 不触发 window resize，所以切换后手动调了一次已有的 resize 逻辑，让 canvas 跟着新尺寸走；右上角「✕ 退出铺满」点一下恢复正常页面。
- **修全屏**：`.player:fullscreen` 时去掉 16:9 比例限制，播放器真正铺满整个屏幕，上下不留黑边；进出全屏时也手动调一次 resize，让 canvas 跟着填满。
- **平时播放器放宽**：`.app` 的 960px 宽度上限放宽到 1600px，大窗口里播放器不再卡在中间的小框里；手机上保持原来的样子不变。
- **视角放宽**：220° 沉浸和 360° 球幕的相机视野从 75° 放到 90°，一眼看到的画面更多、包围感更强；影院模式保持 75° 不动，避免曲面屏边缘拉伸。

其他功能都没动：选本地视频、三种模式切换、WebXR 按钮、PWA manifest、拖动视角、所有文案。

## 诚实说明

- 普通视频在 220° 沉浸模式下是拉伸填充的，看的是环绕感，不是真 360；拉伸比原来 360° 球幕小得多。
- WebXR 的沉浸模式只在支持的浏览器上出现；Vision Pro 的 Safari 目前对 WebXR 的支持有限，如果按钮没出现，就是当前浏览器不支持，球幕/影院模式照常能用。
- v0.1 没有做的：字幕、倍速、播放列表、视频预处理（把普通视频转成 360 需要重拍或 AI 生成，那是另一个活）。
